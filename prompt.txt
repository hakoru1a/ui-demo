# Convention Guide - Implement Feature Screen

## Yêu cầu chung

- Tuân theo cấu trúc và convention của các feature hiện có (suppliers, forest-areas)
- **QUAN TRỌNG**: Check page route và file `docs/features.md` nếu đã có folder rồi thì đừng tạo folder
- Không tự ý tạo thêm folder, nếu cần thiết confirm trước khi tạo (*)
- Structure là Featurebase architecture với convention đã có sẵn
- Luôn cố gắng hướng tới việc tách logic ra khỏi component (PureComponent)
- UI width/height/size cố gắng giống nhất theo convention, không tự ý thay đổi
- Đảm bảo tiêu chí: less code - dễ đọc, dễ bảo trì và đúng convention
- **Chạy eslint trước khi báo xong**

## Quy tắc code

- Không dùng dayjs trực tiếp, dùng `dateHelper` trong utils
- Không dùng magic string, hãy khai báo enum hoặc constant
- Delete item: các dòng phải hiện icon, nếu không đủ điều kiện delete thì disable
- Nếu là ListPage: bổ sung func deleteBulk và delete item

---

## 1. Cấu trúc Types

### Files trong `types/`:
- **entity.ts**: Interface cho entity chính (tương ứng với database model)
- **form.ts**: Interface cho form data (có thể khác entity, ví dụ: File vs string URL)
- **enums.ts**: Enum types (dùng union type string literal)
- **constants.ts**: Options cho select, URLs, constants
- **index.ts**: Export tất cả types để các feature khác có thể import

### Naming:
- Types: PascalCase (ví dụ: `ForestArea`, `ForestAreaFormData`)
- Constants: UPPER_SNAKE_CASE (ví dụ: `STATUS_OPTIONS`)

---

## 2. Validation

- Sử dụng Yup để tạo validation schema
- Định nghĩa `defaultValues` cho form
- Export `schema` và `defaultValues` từ `validation/index.ts`

---

## 3. Components

### Form Component
- Nhận prop `mode: 'create' | 'edit' | 'view'`
- Sử dụng `useFormikContext` để lấy values, errors, touched
- Sử dụng `Grid container` với `spacing={3}`
- Chia sections với `Typography variant="subtitle1"`
- Sử dụng FieldComponents từ `components/fields`
- Xử lý file upload với `SingleFileUpload` từ `components/third-party/dropzone`
- Convert file/string sang `CustomFile[]` cho dropzone

### Table Component
- Sử dụng react-table (tanstack/react-table)
- Sử dụng custom hook `use[FeatureName]Table`
- Hỗ trợ pagination, sorting, filtering, row selection

### Field Types
- `TextField`: Text input
- `NumberField`: Số
- `SelectField`: Dropdown
- `DatePickerField`: Date picker
- `AutocompleteField`: Autocomplete
- `CheckboxField`: Checkbox
- `ToggleField`: Toggle switch
- `SingleFileUpload`: File upload (hình ảnh, tài liệu)

### Form Sections
- Chia form thành các sections với `Typography variant="subtitle1"`
- Mỗi section có `Grid container spacing={3}`
- Fields sử dụng `Grid size={{ xs: 12, sm: 6, md: 4 }}` hoặc tương tự

---

## 4. Pages

- **ListPage**: Sử dụng `MainCard`, `TableHeader`, `Table`, `ConfirmDialog`
- **CreatePage/EditPage**: Sử dụng Formik với validation schema, `MainCard` với action buttons
- **DetailPage**: Hiển thị thông tin read-only, có button Edit

---

## 5. API

- Tạo service class extends `BaseService`
- Export singleton instance
- Các methods: `getList`, `getById`, `create`, `update`, `delete`, `bulkDelete`

---

## 6. Routes

- Sử dụng lazy loading với `Loadable`
- Cấu trúc routes:
  - `/feature-name` (List)
  - `/feature-name/:id` (Detail)
  - `/feature-name/new` (Create)
  - `/feature-name/:id/edit` (Edit)

---

## 7. Hooks

- `use[FeatureName]Table`: Custom hook cho table logic, trả về table instance, filters, data
- `use[FeatureName]Delete`: Hook quản lý delete state và API calls
  - Trả về: `confirmDialog`, `selectedItems`, `isDeleting`, `isBulkDelete`, `handleDelete`, `handleBulkDelete`, `handleConfirmDelete`, `handleCancelDelete`

---

## 8. Naming Conventions

- **Folder**: kebab-case (ví dụ: `forest-areas`)
- **Component files**: PascalCase (ví dụ: `ForestAreaForm.tsx`)
- **Types**: PascalCase (ví dụ: `ForestArea`, `ForestAreaFormData`)
- **Constants**: UPPER_SNAKE_CASE (ví dụ: `STATUS_OPTIONS`)
- **Hooks**: camelCase với prefix "use" (ví dụ: `useForestAreasTable`)

---

## 9. Comments & Language

- Mỗi file bắt đầu với comment header: `// ==============================|| FEATURE NAME ||============================== //`
- Sử dụng tiếng Việt cho labels, placeholders, messages
- Comment các field trong types với mô tả ngắn gọn

## 10. Status & Filters

### StatusTabs Component
- Tạo component `StatusTabs` trong TableHeader file
- Sử dụng `Tabs` và `Tab` từ `@mui/material`
- Tính toán `statusCounts` từ `table.getPreFilteredRowModel().rows`
- **QUAN TRỌNG**: Mỗi status phải có màu riêng biệt, không được trùng nhau
- Màu sắc mapping:
  - `all`: `theme.palette.primary.main`
  - Status tích cực (active, ready, running): `success.main` hoặc `info.main`
  - Status tiêu cực (inactive, maintenance): `error.main` hoặc `warning.main`
  - Status trung tính (new, pending): `grey[600]` hoặc `default.main`
  - Status hoàn thành (completed): `success.main`

```typescript
const getTabColor = (value: StatusFilter) => {
  switch (value) {
    case 'all': return theme.palette.primary.main;
    case 'active': return theme.palette.success.main;
    case 'inactive': return theme.palette.error.main;
    // ... các status khác với màu riêng
    default: return theme.palette.primary.main;
  }
};
```

- Tab indicator có màu theo status
- Count badge có background màu nhạt (`color + '20'`) và text màu đậm
- Render StatusTabs ở đầu TableHeader (trước Toolbar)

### FilterPopover Component
- Tạo component `FilterPopover` trong TableHeader file
- Sử dụng `Popper` từ `@mui/material`
- Import: `useTableFilterDialog`, `useBoolean`, `Transitions`, `ClickAwayListener`
- Props: `open`, `onClose`, `anchorEl`, `columnFilters`, `onFilterChange`
- Structure:
  - Popper với `placement="bottom-end"`, transition, offset
  - Paper với elevation, shadow, responsive width
  - MainCard với title hiển thị "Bộ lọc" + `activeFilterCount` badge
  - Grid container với các filter fields
  - Action buttons: Hủy, Đặt lại (`handleReset`), Áp dụng (`handleApply`)

- Filter fields:
  - `TextField` cho text search (name, code, ...)
  - `SelectField` cho dropdown (type, status, region, ...)
  - `CheckboxField` cho multi-select
  - `NumberField` hoặc `TextField type="number"` cho range
  - `DatePickerField` cho date range (LUÔN dùng `dateHelper.formatDate`)

- Mỗi field có id tương ứng với column id trong table
- Options cho SelectField: `[{ value: '', label: 'Tất cả' }, ...OPTIONS]`

- Trong TableHeader:
  - Sử dụng `useBoolean()` để quản lý filterPopover state
  - Sử dụng `useRef()` để lưu filterAnchorRef
  - Thêm IconButton với `FilterOutlined` icon trong Toolbar

### Search & Export
- Search: TextField với `SearchOutlined` icon trong Toolbar
- Export: CSVExport component trong TableHeader

## 11. Delete Functionality

### Single Delete
- Thêm `DeleteOutlined` icon trong Actions column
- Khi click: Gọi `handleDelete(item)` từ hook
- Mở ConfirmDialog với title "Xác nhận xóa [item name]"
- Hiển thị thông tin chi tiết item trong dialog
- Sau khi confirm: Gọi API delete, update state, show notification

### Bulk Delete
- Thêm `DeleteOutlined` icon trong TableHeader toolbar
- Chỉ hiển thị khi có rows được chọn (`selectedRows.length > 0`) và đủ điều kiện (ví dụ: chỉ draft mới xóa được)
- Khi click: Gọi `handleBulkDelete(selectedRows)` từ hook
- Mở ConfirmDialog với title "Xác nhận xóa nhiều [items]"
- Hiển thị số lượng và danh sách items trong dialog
- Sau khi confirm: Gọi API bulkDelete, update state, show notification

### Hook Pattern
- Tạo `use[FeatureName]Delete` hook
- Quản lý state: `confirmDialog`, `selectedItems`, `isDeleting`, `isBulkDelete`
- Methods: `handleDelete` (single), `handleBulkDelete` (multiple), `handleConfirmDelete`, `handleCancelDelete`
- Callback `onSuccess` để update parent state sau khi delete thành công

### Implementation trong ListPage
- ✅ **ĐÚNG** - Setup đầy đủ bulk delete:
```typescript
// 1. Import use[FeatureName]Delete hook
import { useContractsDelete } from '../hooks/useContractsDelete';

// 2. Setup delete hook với onSuccess callback
const {
  confirmDialog,
  selectedItems,
  isBulkDelete,
  handleDelete,
  handleBulkDelete,
  handleConfirmDelete,
  handleCancelDelete
} = useContractsDelete({
  onSuccess: () => {
    // Update local state after delete
    if (isBulkDelete) {
      const idsToDelete = selectedItems.map((item) => item.id);
      setItems((prev) => prev.filter((item) => !idsToDelete.includes(item.id)));
    } else if (selectedItems.length > 0) {
      const itemId = selectedItems[0].id;
      setItems((prev) => prev.filter((item) => item.id !== itemId));
    }
  }
});

// 3. Memoize delete handler để tránh re-render
const handleDeleteMemo = useCallback(
  (item: Entity) => {
    handleDelete(item);
  },
  [handleDelete]
);

// 4. Pass onBulkDelete vào TableHeader
<EntityTableHeader
  table={table}
  onBulkDelete={handleBulkDelete}  // ✅ Pass bulk delete handler
  // ... other props
/>

// 5. Setup ConfirmDialog với logic cho cả single và bulk delete
<ConfirmDialog
  open={confirmDialog.open}
  onClose={handleCancelDelete}
  onConfirm={handleConfirmDelete}
  title={isBulkDelete ? 'Xác nhận xóa nhiều [items]' : 'Xác nhận xóa [item]'}
  message={
    isBulkDelete
      ? `Bạn có chắc chắn muốn xóa ${selectedItems.length} [items] đã chọn?`
      : selectedItems.length > 0
        ? `Bạn có chắc chắn muốn xóa [item] ${selectedItems[0].name}?`
        : ''
  }
  confirmText="Xóa"
  cancelText="Hủy"
  confirmColor="error"
  data={
    selectedItems.length > 0 && !isBulkDelete
      ? [
          { label: 'Mã', value: selectedItems[0].code },
          { label: 'Tên', value: selectedItems[0].name },
          // ... other fields
        ]
      : []
  }
/>
```
- ❌ **SAI** - Thiếu bulk delete:
```typescript
// Không có use[FeatureName]Delete hook
// Không pass onBulkDelete vào TableHeader
<EntityTableHeader
  table={table}
  // ❌ Thiếu onBulkDelete
/>
// Không có ConfirmDialog cho bulk delete
```
- **Lưu ý**:
  - Luôn implement cả single delete và bulk delete
  - Bulk delete button chỉ hiển thị khi có rows được chọn và đủ điều kiện
  - Update state trong `onSuccess` callback sau khi delete thành công
  - ConfirmDialog phải xử lý cả single và bulk delete với `isBulkDelete` flag

## 15. Common Build Errors & Fixes

### Import Types
- ✅ **ĐÚNG**: `import type { Entity, EntityFormData } from '../types';`
- ❌ **SAI**: `import type { Entity } from '../types.ts';`
- ❌ **SAI**: `import type { Entity } from '../types/index';`
- TypeScript tự động resolve `'types'` -> `'types/index.ts'`

### Empty types.ts files
- Nếu có folder `types/` với `index.ts`, KHÔNG tạo file `types.ts` ở parent directory
- File `types.ts` trống sẽ gây lỗi "File is not a module"
- Xóa file `types.ts` nếu đã có `types/index.ts`

### API Service Type Errors
- ✅ **ĐÚNG**: `this.post<Record<string, never>, Response>(url, {})`
- ❌ **SAI**: `this.post<never, Response>(url, {})`
- Khi dùng post/put với empty payload, dùng `Record<string, never>` thay vì `never`

### Enum Values
- Đảm bảo enum values khớp với usage trong constants và mock data
- Nếu thêm value mới vào constants, phải thêm vào enum type
- Ví dụ: Nếu constants có `'dispatched'`, enum phải có: `'available' | 'busy' | 'off' | 'dispatched'`

### DateTime Handling in FilterPopover
- ✅ **ĐÚNG**:
```typescript
onChange={(value) => {
  const dateStr = value ? dateHelper.formatDate(value, 'YYYY-MM-DD') : undefined;
  handleFilterChange('dateField', dateStr);
}}
```
- ❌ **SAI**: `onChange={(value) => handleFilterChange('date', value ? value.toString() : undefined)}`
- ❌ **SAI**: `onChange={(value) => handleFilterChange('date', value ? value.toISOString() : undefined)}`
- **Lý do**: `dateHelper` đảm bảo format nhất quán và xử lý timezone đúng cách

### Infinite Re-render khi chọn checkbox trong Table
- **Triệu chứng**: Khi click checkbox để chọn row, component bị re-render vô hạn
- **Nguyên nhân**:
  - Callbacks (`onEdit`, `onDelete`, `onSelectionChange`) không được memoize, tạo function mới mỗi lần render
  - Filter functions không được memoize, tạo function mới mỗi lần render
  - Filtered data không được memoize, tính toán lại mỗi lần render
- ✅ **ĐÚNG**:
```typescript
// Trong ListPage
import { useCallback, useMemo } from 'react';

// Memoize filter function
const statusFilterFn = useCallback(
  (item: Entity) => {
    if (statusFilter === StatusFilter.ALL) return true;
    return item.status === statusFilter;
  },
  [statusFilter]
);

// Memoize filtered data
const filteredData = useMemo(() => data.filter(statusFilterFn), [data, statusFilterFn]);

// Memoize callbacks
const handleDeleteMemo = useCallback(
  (item: Entity) => {
    handleDelete(item);
  },
  [handleDelete]
);

// Pass memoized callbacks to table hook
const { table } = useEntityTable({
  data: filteredData,
  onDelete: handleDeleteMemo,
  // ...
});
```
- ❌ **SAI**:
```typescript
// Tạo function mới mỗi lần render
const statusFilterFn = (item: Entity) => item.status === statusFilter;
const filteredData = data.filter(statusFilterFn);
const { table } = useEntityTable({ data: filteredData, onDelete: handleDelete });
```
- **Lý do**:
  - `useCallback` đảm bảo function reference ổn định giữa các lần render
  - `useMemo` tránh tính toán lại không cần thiết
  - Callbacks ổn định giúp `useSelectionChange` không trigger re-render vô hạn
- **Trong useEntityTable hook**: Chỉ enable `useSelectionChange` khi có callback:
```typescript
useSelectionChange(selectedRows, !!onSelectionChange, onSelectionChange ? handleRowSelectionChange : undefined);
```

## 16. General Notes

- Tất cả imports phải đúng path
- Sử dụng TypeScript strict mode
- Export types để có thể share giữa các features
- Follow existing patterns trong suppliers và forest-areas
- Code phải clean, có comments rõ ràng
- Sử dụng Material-UI components từ `@mui/material`
- Icons từ `@ant-design/icons`
- Có thể tạo mock data trong pages hoặc `mock/` folder để test
